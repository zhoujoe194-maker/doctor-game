# doctorgame 全 UI 重设计

2026-11-22。基线 `aab91be13ac54afb5af03ae8d78b737dcb4ea444`，分支 `codex/player-experience-review`。
对应 GitHub issue #5 / 草稿 PR #4。用户要求整站 UI 重设计，而不是继续给旧界面做局部配色；
参考官方 Aimlabs Play 2.0 的深灰/炭黑 + 青色操作色，但不复制其商标、插画、商城或排行榜。

## 设计读取

这是给 VALORANT 玩家用的本地录像复盘工具，不是管理后台、营销页或数据看板。核心任务顺序是：
录/导入 → 选窗口录制 → 赛后看真实录像 → 在真实录像上确认片段 → 得到可解释的复测建议。
界面应该像一个克制的 FPS 工具：真实画面优先、任务区域不对称、层级靠空间和分隔线而不是一叠卡片；
在 1440×900 和 1280×720 打开时，玩家不用滚到页面底部才能继续或确认。

## 类型

- 系统中文栈：`PingFang SC`, `Microsoft YaHei`, `Noto Sans CJK SC`；Windows 和 macOS 都本地可用。
- 字阶：页面 h1 30/1.15；区块 h2 18；卡标题 16；正文 14/1.6；辅助 12。参数和时间使用
  `font-variant-numeric: tabular-nums`，不使用装饰性 mono。
- 字重只用 400/600/650；标题左对齐；正文控制在 60–75ch。
- 不加大写 eyebrow、编号 01/02、渐变文字或营销口号。

## 首访：单一主任务 + 紧凑设置

```text
┌───────────────────────────────────────────────┬─────────────────────┐
│  录制一局                                     │  当前设置            │
│  选择完整游戏窗口，结束后分析                  │  DPI 800   0.350     │
│                                               │  默认值 · 待核对      │
│  [● 开始录制]  [导入已有录像]                  │  [编辑档案]          │
│  手动选窗 · 不录音 · 结束分析                  │                     │
│                                               │  旧报告保留当时设置   │
│  先看合成示例 →                               │                     │
└───────────────────────────────────────────────┴─────────────────────┘
```

左侧 7 列主任务、右侧 5 列设置；不出现巨型空视频、准星占位、宣传语或空的“最近一局”大卡。

## 回访：真实上一局在最前

```text
┌───────────────────────────────────────────────┬─────────────────────┐
│ 继续上一局                                    │  当前设置            │
│ ┌───────────────────────────┐ ┌─────────────┐ │  DPI 800 / 0.350     │
│ │ 真实视频缩略图 + 时长      │ │ 日期/标题   │ │  [编辑档案]          │
│ │                           │ │ 1/20 已量化 │ │                     │
│ └───────────────────────────┘ │ 待确认 0    │ │  录下一局            │
│                               │ [继续复盘]  │ │  [开始录制][导入]    │
│                               └─────────────┘ │                     │
└───────────────────────────────────────────────┴─────────────────────┘
```

真实录像画面是第一视觉；进度和继续动作紧贴画面。录制/导入是第二组操作，不与上一局同等抢眼。
1280×720 首屏可见继续按钮与档案设置；视频保持真实媒体比例，不撑成页面空占位。

## 录制 / 等待 / 选窗

```text
┌─────────────────────────────────────────────────────────────────────┐
│ ● 正在录制  00:37                                      [结束并分析] │
│ ┌─────────────────────────────────────────────────────────────────┐ │
│ │ 真实窗口预览（大）                                               │ │
│ └─────────────────────────────────────────────────────────────────┘ │
│ 已收到画面 · 关闭窗口后仍在托盘录制                                  │
└─────────────────────────────────────────────────────────────────────┘
```

等待画面时同一位置显示状态、重选、取消；选窗弹窗为缩略图网格，Escape/关闭回焦录制按钮。
忙碌/分析进度占同一任务区，取消按钮明确保留录像。

## 复盘：视频左、队列与判断右

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 赛后复盘  合成测试对局.webm · 00:06 · 800 DPI          [导出报告]  │
├───────────────────────────────────────────────┬─────────────────────┤
│ ┌───────────────────────────────────────────┐ │ 1/20 已量化  0 待确认│
│ │ 真实录像（大，保持比例）                   │ │ 建议：保持 0.35     │
│ │                                           │ │ 原因：需要 20 个…   │
│ └───────────────────────────────────────────┘ │ ─────────────────── │
│ 时间线 + 位置                                 │ 片段队列（筛选）     │
│ [回放] [0.5× 慢放] [下一片段]                 │ │ 00:03 对枪 已确认  │
│                                               │ │ 00:00 待确认       │
│                                               │ ├───────────────────┤ │
│                                               │ 本片段：场景/判断    │ │
│                                               │ [排除] [确认有效]   │ │
└───────────────────────────────────────────────┴─────────────────────┘
```

- 大视频保留真实画面和比例；慢放、跳转、确认/排除都在右栏或紧邻视频，1440×900 与 1280×720 首屏可达。
- 顶部不再放大面积统计；样本数、待确认、建议与原始 `recommend()` reason 收进右上紧凑信息行。
- 零候选时右栏直接显示“播放完整录像 / 手动标记关键事件 / 导入另一段录像”，手动标记不折叠。
- 轨迹、建议依据等二级信息放在下方折叠区；视频不加滤镜。

┌─────────────────────────────────────────────────────────────────────┐
│ 对局记录  12 段录像 · 仅保存在本机             [导入录像] [文件夹]  │
├─────────────────────────────────────────────────────────────────────┤
│ 今天                                                                │
│ ┌──────────┐ ┌──────────┐ ┌──────────┐                              │
│ │ 真实缩略 │ │ 真实缩略 │ │ 真实缩略 │  每张卡：标题/状态/时长/DPI  │
│ └──────────┘ └──────────┘ └──────────┘                              │
│ 昨天                                                                │
│ …                                                                   │
└─────────────────────────────────────────────────────────────────────┘

- 按日期分组，真实视频缩略图懒加载：只加载进入视口的卡，生成后释放 blob URL；坏预览保留录像和可点击入口。
- 不做无必要的搜索/过滤/分页；保留导入、打开文件夹、合成示例。

## 档案：紧凑设置，不做营销旁栏

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 玩家档案  当前设置仅影响之后的分析              [保存并返回]         │
├──────────────────────────────────┬──────────────────────────────────┤
│ 游戏与鼠标                        │ 瞄准方式                         │
│ DPI[800] 灵敏度[0.350] 颜色[黄]   │ ○手臂 ○手腕 ●混合 ○不确定        │
├──────────────────────────────────┼──────────────────────────────────┤
│ 握姿                              │ 空间与控制感                     │
│ ○趴握 ○抓握 ○指握 ○不确定         │ 宽度[35] ○舒适 ○受限 ○紧张      │
└──────────────────────────────────┴──────────────────────────────────┘
  当前参数只用于新录像；旧报告仍显示录制当时的档案。
```

去掉营销文案、Why-it-matters 侧栏和装饰编号；帮助文本只在字段旁按需出现。保存和返回始终可达。

## 帮助：实际问题和边界

不再用 01/02/03 步骤模板。以问题分组：录像在哪/怎么停止、为什么要手动确认片段、
建议值怎么来的（20 个样本、方向占比、Wilson 下界）、没有候选怎么办、哪些事项尚未验证。
保留“未获 Riot 审核/未验证 Windows 实机”的边界说明。

## 自评

- 第一版容易变成“把左栏改成顶栏、所有页仍是同样大卡片”。本版强制每页不同任务构图：
  首访是 7/5 主任务+设置，回访是真实录像+信息，复盘是视频工作区+检查器，记录是按日期媒体库，
  档案是双列设置，帮助是问答；没有统一 card 骨架。
- 顶部导航保留操作色只在当前任务和选中态；不把全部按钮做成青色，不加大圆角/玻璃/渐变/每块 eyebrow。
- 去掉空视频、空最近一局、重复页标题、空统计行、营销侧栏和编号步骤。
- 所有空态、错误、禁用、焦点、暗色输入与播放控件统一；视频不染色；不伪造真实录像或统计。
- 不引入新框架或依赖；保留录制/分析/存储/安全边界；测试选择器按新结构维护，行为断言不删除。

## 实现结果与验证（2026-11-22）

实现范围：`src/app.js`（视图层、顶部导航、首访/回访/录制/记录/档案/帮助/复盘结构、历史缩略图生命周期）、
`src/styles.css`（整站布局与组件样式）、`src/tokens.css`（新工具色/间距 token），以及本设计文档和 UI 回归测试。
`src/analysis.js`、`src/storage.js`、`src/media.js`、Electron 安全/采集代码与存储标识未改。

页面最终决定：

- **外壳**：顶部导航居中“录制 / 对局记录”，brand 在左，档案/帮助在右；没有固定左栏。录制/等待状态在非录制页以状态条跨页显示，停止/取消入口始终可达。
- **首访**：h1 为页面语义标题，主卡“录制一局”与“开始录制 / 导入录像”为首要任务；右侧是当前设置与默认值核对。没有空视频、装饰准星或空的最近一局。
- **回访**：真实上一局视频在主区，信息条给出日期、标题、量化/待确认进度和继续复盘；右侧是紧凑设置与下一局入口。继续复盘是唯一主按钮，录制/导入为同组次级操作。1280×720 下继续按钮、设置和录制入口均在首屏。
- **录制/等待**：大预览、状态、计时、结束并分析相邻；等待画面有取消/重选；选窗弹窗为缩略图网格，空窗口/拒绝有恢复。
- **复盘**：左侧大视频 + 时间线 + 回放/慢放控件；右侧紧凑样本、建议与原始 reason、片段队列、本片段场景/判断/确认/排除；轨迹/依据折叠。1440×900 与 1280×720 首屏均可见回放、确认/排除和慢放。
- **对局记录**：按日期分组，真实视频缩略图按视口懒加载（最多 2 个并发），生成后释放 blob URL；坏预览显示“无法预览”但保留录像入口；保留开始录制、导入、文件夹与合成示例。
- **档案**：2×2 紧凑设置区（游戏参数、瞄准方式、握姿、空间控制感），没有营销侧栏；顶部状态、字段旁帮助和底部保存条；旧报告快照说明保留。
- **帮助**：以实际问题和限制分组，没有 01/02/03 编号或营销文案。
- **弹窗/空态/错误/禁用/焦点**：统一暗色控件、青蓝焦点和状态色；窄屏 390/320 无横向溢出。
- **旧报告读取边界**：主页/记录/打开报告都先校验 `events` 数组与档案；损坏报告只降级显示“报告无法读取”与提示，不阻断首页或导航，不把当前 profile 写进旧报告、不删除/迁移/静默重算覆盖原报告，录像字节保持不变。`events:null` 与非法 `profile` 都覆盖。
- **可读性**：导航/按钮/输入/选择器正文 14px；表单 label 13px、字段说明/场景/状态/样本/筛选 label 12px（不再使用 10–11px）；建议原因 13px、帮助正文 14px。首访录制卡删除与描述重复的 fact 列表，只保留“不录制音频 · 支持 MP4 / WebM · 单文件最多 2 GB”和示例入口。

限制：

- 以上为浏览器 Chromium 合成素材实测；本机 DSH 仍有 `ELECTRON_RUN_AS_NODE`/Chromium sandbox 限制，plain Electron smoke 不通过，不能用测试包装伪称全绿。负责人需在 normal sandbox host 独立运行 `tests/player-flow-audit.mjs`、`electron-smoke`、`electron-recovery` 并复核 Electron 窗口初始背景。
- 没有 Windows 游戏实机、原生采集、Vanguard、长录制或性能结论；历史懒加载只在单条/少量合成录像下验证，未做大量长录像压力测试。
- 200% 缩放用 720×450 CSS 视口近似，不是 Electron `setZoomFactor(2)` 的完整验收；负责人环境仍需补测。
- 真实录像不染色、不加滤镜；测试截图中的视频为带水印合成素材，不代表真实对局。
- 坏报告回归只覆盖 localStorage 报告字段损坏（非法 profile、events:null），未扩展为存储迁移或自动修复；用户原报告和录像不会被改写。
